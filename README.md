# WAD-18 Compute Capsule
Zero-dependency C99. `make run` builds at -O0 and -O3, runs 1,000,000 control cycles, checks traces are bit-identical.
`make cross` compares aarch64/riscv64 under qemu-user if installed (otherwise SKIPPED, never faked).

- core/: WAD-18 (int64, scale 1e18, range ~±9.22, saturating + sticky overflow flag), exact 128-bit helpers, SHA-256.
- breakthrough/: R^3 exact discrete critical damping. (a+w)^2 = 4w, a = 2*sqrt(w)-w, solved by recursive bisection on an exact 128-bit predicate.
- benchmark/: certificate checks C1-C5 and the 1M-cycle hashed trace.

Honest scope: critical damping is classical; the contribution is an exact, rounding-free discrete design with machine-checked
integer certificates (not a Coq/Lean proof). Cross-ISA identity is guaranteed by construction (integer-only, endian-independent
hashing) but only verified here on the build host.

## Verification pipeline
`make verify` = build (-O0/-O3) + run 1M cycles + bit-exact compare + regenerate sweep_data and diff against stored + verify ledger.jsonl hash chain. Exits nonzero on any mismatch.
Files: CSL.log (genesis ledger), ledger.jsonl (chained entries incl. iteration_history of failures), sweep_data/*.json.
- multiaxis: 3 axes (different m,k) via R3; included in make verify.
- wad128: core/wad128.* (WAD-18 in 128-bit limbs, +-1.7e20), breakthrough/r3_128.*; differential-tested against the 64-bit core; -Werror on.
- validation: oracle (native int128), bigoracle (independent 32-bit-limb bignum + ties), mutate (fault-injection gate). All in make verify.
- speed: udiv skips leading zero bits (exact-equivalent; ~1.7x on test host). mutate gate now 6 mutants.
- floatbase: double vs WAD-18 across 5 build configs; WAD invariant, double varies (4 hashes); double MORE accurate (vs long double ref). make verify ~40s.
- osc: accumulating-error oscillator vs binary128 ref; WAD wins only at magnitudes >~0.1-1, double wins small; overflow flagged loudly. In make verify (~46s).

## Audit notes (ledger entry 26)
- "R3" here means only the integer bisection in breakthrough/; it is not the operator's broader framework.
- Ledger `closure:true` means "all automated gates passed", not "proven".
- `make verify` now also requires the latest ledger entry's capsule_src_sha256 to match the current source (tools/srchash.sh).
- Ledger values from entries 16 on were transcribed by hand from run logs (open item): the chain proves order/integrity, not truth.
- Mutation gate: 7 killed (incl. a carry reachable only by crafted operands, tested in benchmark/wad128_bigoracle.c); 2 mutants argued unreachable.

## Sealing workflow (F7 follow-up)
- `make verify`  : all gates (incl. tamper self-test) + ledger chain + latest entry machine-sealed + evidence re-extracted from this run's logs. ~51 s on the test host.
- `make seal`    : runs all gates, then appends a machine-generated entry (tools/collect.sh -> tools/seal.sh). Run after any source change.
- Limits: entries 1-26 predate sealing (hand-written); anyone with write access to the whole capsule can regenerate it consistently, so this is tamper-evidence against accidents/outsiders, not against the author.

## Reentrancy
